# Fonts — самохостинг брендовых шрифтов

Шрифты живут **здесь**, в `src/assets/fonts/`, а не в `public/fonts/`: через
Vite файл получает хеш в имени, попадает в `/_astro/` и кэшируется на год
(`Cache-Control: immutable`); из `public/` шрифт ревалидируется на каждом
переходе — два лишних round-trip к рендер-критичному ресурсу.

Не хотлинковать Google Fonts — медленнее, хуже приватность, вопросы по
152-ФЗ/GDPR.

## Порядок

1. Скачать WOFF2 (variable-шрифт = один файл на все начертания). Диапазон
   весов брать максимальный доступный: при более узком браузер молча
   откатится на ближайший вес, и заголовочные 900 отрисуются жиже задуманного.
2. **Сабсетить** под latin + cyrillic (`glyphhanger`, `fonttools`) — экономия
   3–5×. Кириллицу и латиницу можно разнести по файлам с `unicode-range`.
3. Положить `.woff2` сюда.
4. `@font-face` в `src/styles/global.css` относительным путём
   (`url('../assets/fonts/…')`), `font-display: swap`, навести
   `--font-heading` / `--font-body`.
5. Preload критичного подмножества в `BaseLayout.astro` — импортом `?url`
   из ТОГО ЖЕ файла, что и `@font-face` (см. закомментированный пример в
   `<head>`); разные URL = двойная загрузка шрифта.

Полный канон: `docs/PERFORMANCE.md` §3.

## Сабсетинг латиницы под фактический набор глифов

Готовые «latin»-подмножества (Google/fontsource и подобные) везут всю
Latin-1 с диакритикой и весь блок общей пунктуации — на сайте с нелатинским
основным языком (например, русским) латиница нужна только для отдельных
вкраплений: брендов, цифр, единиц измерения. На боевом проекте скан
собранных страниц нашёл около 90 реально использованных латинских глифов и
ни одного акцентированного — пересборка под фактический набор сократила вес
латинского файла в этом случае почти вдвое (58 → 36 КБ, −37%).

Команда пересборки (после проверки, что каждый вариант начертания реально
используется). `--with-zopfli` в неё не входит: этот флаг переключает
сжатие только для `--flavor=woff` (WOFF1) — для `--flavor=woff2` fontTools
всегда жмёт Brotli, и флаг был бы молчаливым no-op:

```sh
python3 -m venv /tmp/fontenv && /tmp/fontenv/bin/pip install fonttools brotli
UNI='U+0020-007E,U+00A0,U+00A7,U+00A9,U+00AB,U+00B0-00B1,U+00B7,U+00BB,U+00D7,U+00F7,\
U+2013-2014,U+2018-201A,U+201C-201E,U+2020-2022,U+2026,U+2030,U+2039-203A,U+2044,\
U+20AC,U+20BD,U+2122,U+2190-2193,U+2212,U+2215,U+FEFF,U+FFFD'
/tmp/fontenv/bin/pyftsubset <family>-latin.woff2 --unicodes="$UNI" \
  --flavor=woff2 \
  --layout-features='kern,liga,calt,ccmp,locl,mark,mkmk,rlig' \
  --output-file=<family>-latin.woff2
```

Набор глифов в `$UNI` намеренно шире фактических ~90: вся печатная ASCII
плюс типографские знаки и валюты — с запасом на будущий контент, а не под
сегодняшний скан один-в-один. Часть запрошенных кодпоинтов в конкретном
семействе может просто отсутствовать (не все шрифты несут стрелки, `₽`,
`‰`) — `pyftsubset` молча их пропускает, это нормально.

**Правило, которое нельзя нарушать: набор глифов в файле и `unicode-range`
в `@font-face` меняются ВМЕСТЕ, одним коммитом.** Врать можно в обе
стороны:

- символ, объявленный в `unicode-range`, но которого физически нет в файле,
  не заставит браузер скачать этот файл лишний раз, но при попытке им
  отрисовать символ произойдёт молчаливый откат на системный шрифт —
  ровно так уже случалось с диапазоном стрелок (`U+2191`/`U+2193`),
  заявленным в `unicode-range`, но вырезанным из файла при прошлой
  пересборке;
- символ, который есть в файле, но не входит в объявленный `unicode-range`,
  никогда не подгрузит этот файл браузером — тот же откат на системный
  шрифт, только по другой причине.

`unicode-range` в `global.css` поэтому **генерируется из cmap готового
файла**, а не пишется на глаз:

```sh
/tmp/fontenv/bin/python - <<'EOF'
from fontTools.ttLib import TTFont
f = TTFont('src/assets/fonts/<family>-latin.woff2')
cps = sorted({c for t in f['cmap'].tables for c in t.cmap} - {0})
out, s, p = [], cps[0], cps[0]
for c in cps[1:]:
    if c == p + 1: p = c; continue
    out.append((s, p)); s = p = c
out.append((s, p))
print(', '.join(f'U+{a:04X}' if a == b else f'U+{a:04X}-{b:04X}' for a, b in out))
EOF
```

Если контент начнёт регулярно приносить новые знаки — расширять набор
глифов и `unicode-range` вместе, в одной правке. Ось веса (диапазон
начертаний variable-шрифта) сабсетингом не трогать — это отдельный параметр
`pyftsubset`, и сужать его следует только вместе с проверкой, что все
используемые `font-weight` остаются внутри диапазона (см. п.1 выше).
