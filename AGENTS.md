# AGENTS.md — правила работы агента в этом репозитории

## Главное правило

**Новый сайт не строится с нуля: берётся этот стартер и переделывается под
проект.** Прежде чем писать что-либо новое — ищи готовое:

1. Каталог компонентов — `docs/AGENT-PLAYBOOK.md` §9 (секции, каталог, формы,
   попапы, аналитика, SEO — почти всё уже есть).
2. Рецепты проверенных боем решений — `docs/recipes/README.md` (таблица со
   статусами: что лежит кодом, что инструкцией).
3. Профильные доки — `docs/` (ARCHITECTURE, IMAGES, SEO, PERFORMANCE, LEGAL,
   CMS-BUILDING, CONTENT) и `docs/en/deploy.md` для контракта с панелью.

Новый код пишется только когда маппинга на готовое нет — и тогда по образцу
ближайшего существующего компонента.

Сборка сайта по HTML-прототипу или дизайн-референсу — скилл **`/new-site`**
(`.claude/skills/new-site/`): он ведёт по фазам AGENT-PLAYBOOK с чек-пойнтами.

## Запреты — нарушение ломает сайт молча

- **Тело `<script is:inline>` НЕ оборачивать в `` {`…`} ``** — Astro выведет
  скобки литералом, скрипт станет мёртвой строкой (так неделями молчала
  Метрика). Регрессия-страж: `src/components/analytics/__tests__/metrika-alive.test.ts`.
- **`defer: true` Метрики и ручные хиты `AnalyticsRouterHit` не менять
  порознь** — defer без ручного первого хита = потерянные просмотры, ручной
  хит без defer = двойной счёт.
- **Контракт согласия не переименовывать порознь**: localStorage
  `cookie-consent` + событие `app:cookie-consent` связывают CookieConsent и
  consent-gate Метрики.
- **С `trailingSlash:'always'` не добавлять редиректы `/x` → `/x/`** — это
  один и тот же роут, получится петля.
- **`set:html={JSON.stringify(...)}` запрещён** — только `serializeJsonLd`
  (закрытая stored-XSS). Тест-страж в `json-ld.test.ts` найдёт нарушение.
- **Санитайзер markdown не отвязывать от процессора.** `markdown: { processor:
  unified({ rehypePlugins: [rehypeSanitize] }) }` — единственная защита от
  stored-XSS в теле товара, которое пишет клиент. Старые поля
  `markdown.rehypePlugins/...` при чужом процессоре выбрасываются молча:
  сборка зелёная, `<script>` уезжает в `dist/` (граблина 19b в
  `docs/recipes/gotchas.md`). Страж — `markdown-sanitizer.test.ts`.
  Изоляцию блога (`mdx({ extendMarkdownConfig: false })`) не снимать: rehype
  работает по HAST и MDX/JSX не нейтрализует.
- **Один eager LCP-кандидат на страницу**; всё остальное lazy
  (`docs/PERFORMANCE.md` §8).
- **`data/` (лиды, PII) не коммитить** — в `.gitignore` не просто так.
- Полный справочник грабель: `docs/recipes/gotchas.md` (боевые уроки двух
  эталонных проектов).

## Рабочий процесс

- Скрипты: бандл-`<script>` по умолчанию; `is:inline` — только verbatim
  (Метрика, JSON-LD, гейты в `<head>`).
- Каждый инлайн-скрипт обязан переживать SPA-навигацию (`ClientRouter`):
  флаг `window.__fooInit`, привязка к DOM в `astro:page-load`.
- Перед коммитом: `npm test` (сборка + vitest, включая замок ниже). Типы:
  `npm run typecheck`.
- Тексты коммитов — на русском, по-делу.
- Static-сборка без адаптера обязана оставаться зелёной: активные
  `prerender = false` роуты не коммитить (для них есть `.example`).
- **Совместимость с CMS-порталом Freim Deploy — не опция**: `data-cms`-
  разметка, генерируемый `content.schema.json` и `fd-edit.js` — контракт, по
  которому клиент редактирует сайт. Новые редактируемые блоки — только по
  `docs/CMS-BUILDING.md`; разметку стерегут `annotations.test.ts` и
  `fd-edit.test.ts`.

## Два железных правила публичного репозитория

Этот репозиторий — витрина: его форкают, ставят из него сайты, читают его
код чужие агенты. Следующие два правила существуют именно для этого и не
подлежат пересмотру по ходу работы.

### 1. `frostdeploy.json` не переименовывается никогда

Файл называется в честь прежнего имени платформы — она называлась
**FrostDeploy**, потом стала **Freim Deploy**. Ребрендинг сознательно не
тронул то, что читают не люди, а машины: путь, команду и — в первую
очередь — это имя файла-манифеста. Серверы, уже установленные у клиентов на
старой платформе, ищут в репозитории ровно файл `frostdeploy.json`, когда
проверяют и накатывают собственные обновления. Переименуй его в
`freimsite.json` или `freim-deploy.json` — и для существующего парка
серверов этот контракт молча перестанет находиться: обновления не сломаются
с ошибкой, они просто перестанут случаться. Подробности и полный разбор
поля за полем — `docs/en/deploy.md`.

Это не забытая уборка и не техдолг. Не «исправляй» это имя ни в коде, ни в
доке, ни в примере.

### 2. Клиентов не называть по имени — нигде

Ни в комментарии, ни в примере пути, ни в тексте рецепта, ни в имени
переменной. Этот шаблон одновременно публичная витрина и личный рабочий
инструмент: рецепты в `docs/recipes/` пишутся по горячим следам сразу после
конкретного клиентского сайта, и имя клиента в них проскакивает
естественно, если не следить специально.

Замок — `scripts/__tests__/public-tree.test.ts` (входит в `npm test`): он
проходит по всем отслеживаемым текстовым файлам и валится, если находит имя
уже известного клиента (латиницей и кириллицей), абсолютный путь из чьего-то
домашнего каталога на macOS или личный адрес почты. Замок знает только те
имена, которые в него уже вписаны, — это не эвристика, а перечисление.

**Когда начинается новый клиентский проект, первым делом добавь корень
нового имени в константы замка** (`CLIENT`, при необходимости — второй
корень для кириллической записи, по образцу уже имеющихся). Без этого шага
имя следующего клиента спокойно попадёт в код и рецепты — замок его просто
не увидит, потому что не знает о нём, — и через несколько проектов утечка
случится снова, той же дорогой, что и в первый раз.
