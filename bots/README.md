# bots/ — боты приёма лидов (Telegram + MAX)

Опциональный приёмник лидов для лид-пайплайна v2 стартера: два
самостоятельных worker-процесса. Каждый поднимает локальный HTTP-приёмник
(`POST /notify` + `GET /health`), принимает от сайта JSON-лид, форматирует
его в карточку с инлайн-кнопками квалификации **✅ Квал / 🔝 Целевой /
❌ Отказ** и постит в рабочий чат. Нажатия кнопок уходят server-side целями
в Яндекс.Метрику (Offline Conversions API — окно 21 день; фолбэк —
Measurement Protocol).

Сайту модуль не обязателен: лид всегда сохраняется на стороне сайта
(persist), notify — best effort. Нужен только один мессенджер — деплойте
только его бота.

**Окружение у проекта одно.** Отдельных `.env` рядом с `bot.py` нет:
переменные и сайта, и обоих ботов живут в общем `.env` сайта (образец со
всеми ключами — `.env.example`), а на проде — в наборе Env проекта в панели
Freim Deploy, который и так достаётся всем сервисам. Бот находит файл сам,
поднимаясь вверх от `bot.py` (проверяет `<каталог>/.env` и
`<каталог>/website/.env` — обе раскладки), и первой строкой лога печатает,
какой именно прочитал.

Подробности пайплайна: `docs/recipes/lead-pipeline.md`.
Памятка менеджера по кнопкам: `docs/recipes/manager-guide.md`.

## Состав

| Каталог | Что делает | Порт /notify (дефолт) |
| --- | --- | --- |
| `telegram/` | aiogram-бот: карточка + вложения ответами под ней, long polling | 8091 |
| `max/` | бот MAX (сырой httpx): текст + вложения + кнопки одним сообщением | 8092 |

⚠️ **Порт уникален на СЕРВЕР, а не на проект.** `8091/8092` — дефолт, а не
бронь: loopback один на всю машину, поэтому второй проект на том же хосте
упадёт с `address already in use`, и упадут ОБА его бота, уронив деплой
целиком. Своя пара задаётся `TELEGRAM_NOTIFY_PORT` / `MAX_NOTIFY_PORT` —
и теми же числами в `LEAD_NOTIFY_URLS` сайта. Реестр выданных пар —
`docs/recipes/lead-pipeline.md` §6.1.

## Контракт /notify

`POST http://127.0.0.1:<порт>/notify`, заголовок
`X-Bot-Secret: <NOTIFY_SECRET>`. Тело — JSON-лид:

```json
{ "lead_id": "uuid", "stage": "complete",
  "created_at": "ISO", "completed_at": "ISO",
  "phone": "+7XXXXXXXXXX", "name": "?",
  "type": "ключ из LEAD_TYPE_LABELS", "message": "?",
  "contactMethod": "phone|messenger", "prefill": "?", "case": "?",
  "source": "ключ из LEAD_SOURCE_LABELS", "page_url": "https://…",
  "client_id": "?", "utm_source": "?", "utm_medium": "?",
  "utm_campaign": "?", "utm_term": "?", "utm_content": "?",
  "yclid": "?", "gclid": "?",
  "attachments": [{ "path": "attachments/<lead_id>/1.jpg",
                    "name": "фото.jpg", "size": 12345, "mime": "image/jpeg" }] }
```

`stage`: `complete` — обычный лид; `flushed` — авто-отправка черновика
(клиент оставил телефон, но не дожал «Отправить» — бот помечает карточку и
шлёт MP-цель `lead_flushed`); `updated` — клиент дополнил заявку после
авто-флаша (бот редактирует ранее отправленную карточку, при неудаче шлёт
отдельную «Дополнение к заявке»).

`attachments[].path` — относительно `DATA_DIR` (общий с сайтом каталог
данных; выход за его пределы отсекается). Ответ `200 {"ok": true}` —
принято в фоновую доставку: ретраи 5 попыток, backoff 2/4/8/16 с, сайт
ответа мессенджера не ждёт. Ошибки: `403 forbidden` (секрет),
`400 bad_json`, `503` (нет токена / не настроен чат).

`GET /health` — uptime, mode (`active` | `waiting_for_token`), счётчики
received/sent/failed, `pending_delivery`; у TG-бота `?deep=1` дополнительно
дёргает `getMe`.

## Переменные окружения

Оба бота читают ОДИН общий набор env — тот же файл, что и сайт (на проде —
набор Env проекта в панели). У ключей, обязанных различаться, есть
префиксное имя (`TELEGRAM_NOTIFY_PORT` против `MAX_NOTIFY_PORT`);
безпрефиксное остаётся фолбэком для посервисных наборов.

⚠️ Безпрефиксный `NOTIFY_PORT` в общем файле задавать НЕЛЬЗЯ: его получат оба
бота, второй не займёт порт и умрёт на старте с понятной, но обидной ошибкой.

Три ключа намеренно называются так же, как у сайта, — значение одно на два
процесса, и разъехаться им негде:

| Ключ | Прежнее имя у ботов |
| --- | --- |
| `LEAD_NOTIFY_SECRET` | `NOTIFY_SECRET` (остался фолбэком) |
| `LEAD_DATA_DIR` | `DATA_DIR` (остался фолбэком) |
| `PUBLIC_YANDEX_METRIKA_ID` | `METRIKA_COUNTER_ID` (остался, если счётчик другой) |

Нестандартная раскладка каталогов (бот лежит не под корнем репозитория) —
укажите файл явно: `SITE_ENV_FILE=/путь/к/.env`.

⚠️ В общем файле переменная присутствует ВСЕГДА, поэтому пустое значение не
должно перебивать дефолт. В коде ботов для этого `_env()` (пустое = не
задано), а не `os.getenv(name, default)`.

| Переменная | Бот | Дефолт | Что это |
| --- | --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` (фолбэк `BOT_TOKEN`) | TG | — | токен от @BotFather; без него бот мирно спит (`waiting_for_token`) |
| `TELEGRAM_GROUP_CHAT_ID` (фолбэк `GROUP_CHAT_ID`) | TG | — | chat_id рабочей группы (команда `/id` в группе) |
| `TELEGRAM_NOTIFY_PORT` (фолбэк `NOTIFY_PORT`) | TG | `8091` | порт приёмника /notify |
| `MAX_TOKEN` | MAX | — | токен из кабинета dev.max.ru; без него бот мирно спит |
| `MAX_CHAT_ID` | MAX | — | chat_id группы MAX (из логов, событие `bot_added`) |
| `MAX_NOTIFY_PORT` (фолбэк `NOTIFY_PORT`) | MAX | `8092` | порт приёмника /notify |
| `MAX_API_BASE` | MAX | `https://botapi.max.ru` | базовый URL MAX Bot API (публичный хост, Let's Encrypt) |
| `RUSSIAN_TRUSTED_CA_PATH` | MAX | — | PEM корневого CA Минцифры; нужен ТОЛЬКО при `MAX_API_BASE=platform-api2.max.ru` |
| `LEAD_NOTIFY_SECRET` (фолбэк `NOTIFY_SECRET`) | оба | — | общий с сайтом секрет заголовка `X-Bot-Secret` (пусто → проверка выключена) |
| `NOTIFY_HOST` | оба | `127.0.0.1` | интерфейс приёмника (наружу не торчать) |
| `LEAD_DATA_DIR` (фолбэк `DATA_DIR`) | оба | — | корень файлового хранилища лидов (`attachments/<lead_id>/…`), общий с сайтом; пусто → вложения не уйдут |
| `METRIKA_COUNTER_ID` (фолбэк `PUBLIC_YANDEX_METRIKA_ID`) | оба | — | номер счётчика Метрики; обычно не задаётся — берётся счётчик сайта. Пусто в обоих → цели тихо пропускаются |
| `METRIKA_MP_TOKEN` | оба | — | токен Measurement Protocol (Настройки счётчика → Measurement Protocol) |
| `METRIKA_OAUTH_TOKEN` | оба | — | OAuth-токен Offline Conversions API (scope `metrika:offline_data`); задан → квал-кнопки идут офлайн-конверсиями (окно 21 день), пуст → фолбэк MP (12 часов) |
| `SITE_HOSTS` | оба | пусто | домены сайта через запятую: их страницы в карточке показываются путём без домена; пусто → warning в лог, страницы показываются с доменом |
| `TZ_OFFSET_HOURS` | оба | `3` | фиксированный офсет времени карточек (МСК) |
| `SITE_ENV_FILE` | оба | — | явный путь к общему `.env`, если автопоиск вверх от `bot.py` не подходит |
| `BRAND_NAME` | оба | `Сайт` | название проекта в заголовках карточек («📩 Новая заявка — …») и текстах команд |
| `LEAD_TYPE_LABELS` | оба | `{}` | JSON-объект `type` → подпись, напр. `{"repair": "Ремонт"}`; неизвестный ключ показывается как есть, битый JSON не роняет бота (warning + дефолт) |
| `LEAD_SOURCE_LABELS` | оба | `{"form": "форма на сайте", "popup": "попап"}` | JSON-объект `source` → подпись источника |

## Цели Метрики

Завести в счётчике как «JavaScript-событие», идентификаторы один-в-один:
`lead_qualified` (✅ Квал), `lead_target` (🔝 Целевой — ключевая цель для
Директа), `lead_rejected` (❌ Отказ), `lead_flushed` (доставка
авто-отправленного черновика; всегда через MP).
