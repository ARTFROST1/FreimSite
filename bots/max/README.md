# MAX-бот приёма лидов

Бот приёма заявок для мессенджера MAX (max.ru). Зеркало Telegram-бота
(`bots/telegram/`): тот же контракт `/notify`, та же карточка, те же кнопки
квалификации и server-side цели Метрики.

Обзор модуля, контракт `/notify` и полная таблица env — `../README.md`.

Один процесс = три вещи:

1. **HTTP-приёмник** `POST /notify` + `GET /health` на `127.0.0.1:8092` —
   сайт шлёт сюда лид, бот постит карточку в группу MAX.
2. **Long polling** `GET /updates` — ловит нажатия кнопок
   ✅ Квал / 🔝 Целевой / ❌ Отказ и событие `bot_added` (для chat_id).
3. **Метрика** — цели `lead_qualified` / `lead_target` / `lead_rejected`
   по кнопкам + `lead_flushed` при доставке авто-отправленного черновика.

## 🔑 Как получить токен

1. Зайдите в кабинет партнёра **dev.max.ru** — вход через аккаунт MAX
   с **верифицированным профилем** (юрлицо / ИП / самозанятый).
2. Создайте бота, заполните карточку (имя, описание, аватар).
3. Бот проходит **модерацию** — до её окончания токен может не работать
   в проде.
4. Полученный токен впишите в `MAX_TOKEN`.

Токен передаётся в API сырой строкой в заголовке `Authorization`
(без `Bearer`) — это бот делает сам.

**Важно:** без токена бот **мирно спит** — процесс живёт, `/health`
отвечает `{"ok": true, "mode": "waiting_for_token"}`, `/notify` отдаёт
`503 {"error": "max_token_not_set"}`. Это сознательно: crashloop
worker-процесса завалил бы деплой всего релиза. Появился токен →
впишите в env и перезапустите сервис.

## 💬 Как поймать chat_id группы

`GET /chats` в API MAX устарел (июнь-2026), поэтому:

1. Создайте рабочую группу в MAX.
2. Добавьте бота в группу **администратором** — без прав админа бот
   не получает события из групповых чатов.
3. В логах сервиса появится строка:
   `Обнаружен chat_id группы: … (событие bot_added)`.
   (Если событие проскочило — напишите любое сообщение в группу, сработает
   ловля по `message_created`.)
4. Впишите значение в `MAX_CHAT_ID` и перезапустите сервис.

## 🤝 Паритет с Telegram-ботом

Карточка собирается тем же кодом-близнецом, что у TG: заголовок с
`BRAND_NAME`, имя жирным, `📋 Тип · Связь`, `🎯 По мотивам`, блок
`💬 Комментарий`, `📊 Аналитика`, время МСК с источником, те же кнопки и
цели Метрики. Отличия — только там, где их диктует платформа:

| | Telegram | MAX |
| --- | --- | --- |
| Файлы | ответами под карточкой (альбом не несёт кнопок) | в том же сообщении — API это умеет |
| Комментарий / аналитика | цитата и сворачиваемая цитата | те же блоки с заголовками: MAX из разметки знает только `b/i/u/s/a/code/pre` |
| Телефон | ссылка `tel:` | обычным текстом |
| Дополнение лида (stage=updated) | правка карточки + реплай-уведомление | то же через `PUT /messages`; если API откажет — отдельная карточка «Дополнение к заявке» |

## 🔐 TLS: доп. сертификаты НЕ нужны

Бот ходит на `https://botapi.max.ru` — публичный хост Bot API с обычным
сертификатом **Let's Encrypt**. Стандартный certifi-бандл Python его знает,
ничего доустанавливать не надо.

Проверка от 2026-08-14 (`openssl s_client` + `curl`):

| Хост | Издатель сертификата | Проверка обычным CA-bundle |
| --- | --- | --- |
| `botapi.max.ru` | Let's Encrypt | ✅ проходит (`ssl_verify_result=0`) |
| `platform-api2.max.ru` | Ministry of Digital Development, `Russian Trusted Sub CA` | ❌ код 20 «unable to get local issuer» |

Все используемые эндпоинты живут на публичном хосте (проверено — без токена
отдают 401, то есть существуют): `GET /me`, `GET /updates`, `GET|POST
/messages`, `PUT /messages?message_id=`, `POST /answers?callback_id=`,
`POST /uploads?type=`.

**Сертификат Минцифры** (Russian Trusted Root CA) — это корневой удостоверяющий
центр, который государство завело в 2022-м, когда западные CA перестали
выписывать сертификаты подсанкционным российским организациям. Браузеры и
Python о нём не знают, поэтому сайты под ним требуют ручной установки корня.
Нам он нужен, **только** если переопределить `MAX_API_BASE` на внутренний
`platform-api2.max.ru`. Тогда:

1. Скачайте корневой сертификат: **https://www.gosuslugi.ru/crt**
   (нужен PEM; при необходимости конвертируйте:
   `openssl x509 -inform der -in russian_trusted_root_ca.cer -out russian_trusted_root_ca.pem`).
2. Положите на сервер, например `/etc/ssl/russian_trusted_root_ca.pem`.
3. Путь укажите в `RUSSIAN_TRUSTED_CA_PATH` — бот соберёт контекст
   «certifi + этот PEM».

Запросы к `mc.yandex.ru` (Метрика) всегда идут через обычный certifi.

## 📥 Контракт /notify

`POST http://127.0.0.1:8092/notify`, заголовок `X-Bot-Secret: <NOTIFY_SECRET>`,
тело — полный JSON-лид (формат и все поля — см. `../README.md`).

Ответ `200 {"ok": true, "queued": true}` = принято в фоновую доставку
(мгновенный ack; ретраи внутри бота — 5 попыток, backoff 2/4/8/16 с).
Пути `attachments[].path` — относительно `DATA_DIR`; изображения заливаются
в MAX (`type=image`), остальное — `type=file`, и прикладываются к самой
карточке (в MAX текст + вложения + кнопки живут в одном сообщении).
Не загрузились — карточка уходит без них со строкой «📎 файл недоступен».

Ошибки: `403 forbidden` (секрет), `503 max_token_not_set`,
`503 chat_not_configured`, `400 bad_json`.

`GET /health` → uptime, mode (`active` | `waiting_for_token`),
chat_configured, счётчики received/sent/failed/callbacks, last_error.

## 🚦 Кнопки и Метрика

На карточке: `[✅ Квал] [🔝 Целевой] [❌ Отказ]`. Нажатие атомарно заменяет
карточку (через `POST /answers`) — внизу появляется футер
«статус · кто · когда»; кнопки остаются, статус можно перещёлкивать.
Карточке больше 24 часов (окно редактирования MAX) — бот шлёт
реплай-сообщение со статусом вместо замены.

Цели Метрики (`client_id` из текста карточки): `lead_qualified`,
`lead_target`, `lead_rejected` + `lead_flushed` при доставке
flushed-карточки. Все четыре завести в счётчике как «JavaScript-событие».
Пустые `METRIKA_*` → отправка тихо пропускается. Квал-кнопки при заданном
`METRIKA_OAUTH_TOKEN` идут через Offline Conversions API (окно привязки
21 день), иначе — фолбэк на Measurement Protocol (12 часов);
`lead_flushed` всегда через MP.

## 🚀 Деплой

Сервис-worker рядом с сайтом (пример для Freim Deploy: runtime python,
role worker, rootDir `bots/max`, run `.venv/bin/python bot.py`,
`requirements.txt` → авто pip+venv). Env — через панель, ключи — см.
`../README.md`. Порт 8092 фиксирован в env, слушает только 127.0.0.1.

Порядок включения: сервис можно катить сразу **без токена** — бот мирно
спит и не мешает релизам. Дальше: получить токен (модерация dev.max.ru) →
`MAX_TOKEN` → рестарт → добавить бота админом в группу → chat_id из логов →
`MAX_CHAT_ID` → рестарт. Готово.

## 🖥 Локальный запуск

```bash
cd bots/max
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
# .env рядом с bot.py НЕ нужен: переменные берутся из общего .env сайта
# (минимум для боевого запуска — MAX_TOKEN и MAX_CHAT_ID).
.venv/bin/python bot.py
```

Проверка без MAX (бот спит):

```bash
curl -s http://127.0.0.1:8092/health | jq
curl -s -X POST http://127.0.0.1:8092/notify \
  -H 'X-Bot-Secret: <секрет>' -H 'Content-Type: application/json' \
  -d '{"lead_id":"test","stage":"complete","phone":"+79001234567","source":"form"}'
```
