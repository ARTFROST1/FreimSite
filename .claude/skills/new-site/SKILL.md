# /new-site — сборка сайта из стартера по референсу

Ты ведёшь полный цикл «референс → готовый сайт». База знаний — `docs/AGENT-PLAYBOOK.md` (фазы, циклы, каталог компонентов, антипаттерны, заготовки); этот скилл — алгоритм поверх неё с фиксированными точками общения с пользователем. Правила репозитория — `AGENTS.md` (главное: **не строить с нуля — переделывать готовое**).

## Шаг 1. Вход

Прими от пользователя: HTML-прототип (файл/каталог) и/или скриншоты/референсы дизайна + бриф (ниша, город, что продаём, что является конверсией). Чего-то нет — спроси ОДНИМ сообщением списком, не по одному. Требования к входу — AGENT-PLAYBOOK §1 (фаза 0).

## Шаг 2. Разбор референса → карта маппинга

По AGENT-PLAYBOOK §2 (фаза 1): разбей референс на секции и для КАЖДОЙ найди маппинг на готовое из каталога §9 (Hero, Intro, Features, Pricing, Reviews, FAQ, Gallery, Map, CTA, StackedShowcase, ScrollScene, каталог, блог, формы, попапы). Результат — таблица «секция референса → компонент стартера → доработка (нет / стили / структура) → новое (только если маппинга нет)». Новых компонентов в типовом лендинге должно быть 0–2; больше — перепроверь каталог.

## Шаг 3. Чек-пойнт: дизайн-токены

Извлеки из референса палитру, шрифтовые пары, радиусы; подготовь значения для `@theme` в `src/styles/global.css`. **Спроси пользователя** (AskUserQuestion): подтвердить палитру/шрифты или дать свои. Шрифты — сразу по канону `docs/PERFORMANCE.md` §3 (`src/assets/fonts/`, сабсет, preload из того же импорта). Логотип: если есть мастер-SVG — `design/logo-master.svg` + `npm run build:icons` (сверить PLATE/FILL_MAP).

## Шаг 4. Чек-пойнт: состав модулей

**Спроси пользователя** (AskUserQuestion, multiSelect) — что нужно проекту:
- каталог товаров (+ structured data по `docs/recipes/catalog-seo.md`);
- блог;
- лид-форма: одношаговая или **двухшаговая с черновиками** (v2, `docs/recipes/lead-pipeline.md`);
- боты приёма лидов TG/MAX (+ офлайн-конверсии) — требуют hybrid-режим;
- consent-gate Метрики (152-ФЗ; дефолт — включён);
- Яндекс.Карта; попапы/промо; товарные фиды (пока TODO-модуль);
- медиа-конвейер разбора фотоархива клиента (`docs/recipes/photo-archive.md`).

По ответу зафиксируй: static или hybrid, какие `.example` активировать, что удалить (неиспользуемые модули вычищаются, а не остаются мёртвым грузом — вместе с их целями в `GOALS` и строками контента).

## Шаг 5. Конфиги из брифа

Заполни: `src/config/site.ts` (ПЕРВЫМ — бренд, контакты, гео) + `SITE_URL` в `astro.config.mjs`, `seo.ts`, `nav.ts` + `src/content/nav/*`, `legal.ts` (что известно; остальное — плейсхолдеры, `placeholder: true` не снимать), `.env.example` → `.env` по составу модулей. Недостающие факты (ИНН, адрес шоурума, реквизиты) собери в ОДИН список вопросов пользователю — не растягивай на десять сообщений.

## Шаг 6. Сборка секций (параллель субагентами)

Для каждой секции из карты шага 2 — задача по циклу AGENT-PLAYBOOK §5 (7 шагов: разметка → токены → контент-коллекция → data-cms → адаптив → reveal → проверка). Независимые секции раздавай параллельным субагентам; каждому в промпт: карта секции, референс, целевой компонент, правила AGENTS.md и антипаттерны §10. Контент — в `src/content/**` (не хардкод), картинки — `src/assets/**` через `<ContentImage>`, ровно один eager LCP-кандидат на страницу.

## Шаг 7. Приёмка

Прогони чек-лист AGENT-PLAYBOOK §8 полностью, плюс обязательные из бэкпорта боевого проекта:
- `npm test` зелёный; `npm run typecheck` — 0 ошибок;
- **Метрика живая**: сборка с тестовым `PUBLIC_YANDEX_METRIKA_ID` → в браузере `typeof window.ym === 'function'`, до согласия ноль запросов к `mc.yandex`, после «Принять» очередь уезжает (браузерный MCP; регрессия metrika-alive.test.ts — не замена живой проверке);
- JSON-LD валиден (тесты + визуальный просмотр `<script type="application/ld+json">`);
- consent/cookie-баннер и правовые страницы на месте; `legal.ts` заполнен или явно оставлен в `placeholder` с пометкой пользователю;
- **якорная навигация**: `npm run audit:anchors` — PASS во всех клетках (SKIP допустим там, где на сайте нет материала: нет якорной ссылки в подвале). Прогнать ТРИЖДЫ: баги здесь флейковые. Если селекторы шапки/липкой обвязки отличаются от умолчаний — сперва поправить их в `src/lib/scroll-to.ts` и `scripts/anchor-audit.mjs`, см. `docs/recipes/anchor-navigation.md` §1;
- OG-картинки в `public/og/`, фавиконки собраны `build:icons`;
- Lighthouse Mobile по `npm run preview`: цель 100×4, минимум — зелёная зона CWV; бюджет первой загрузки — `docs/PERFORMANCE.md` §7 (тяжёлые секции ниже сгиба = 0 КБ на scrollY=0);
- отчёт пользователю: что собрано, что осталось руками (счётчик Метрики и цели по `docs/recipes/metrika-guide.md`, Вебмастер/GSC по `docs/recipes/webmaster-gsc-guide.md`, юрфакты, деплой).

## Правила по ходу

- Застрял на выборе, который меняет структуру сайта — спрашивай пользователя; мелкие решения принимай сам и фиксируй в отчёте.
- Каждая фаза — коммит(ы) с внятным сообщением на русском.
- Прокрутка и якоря: `src/lib/scroll-to.ts` и `src/lib/anchor-nav.ts` менять только прочитав `docs/recipes/anchor-navigation.md`. Там 12 правил, каждое — уже оплаченный баг; нарушение любого возвращает рывки и промахи, которые ловятся только стендом.
- Грабли: перед правкой конфига/скриптов/анимаций сверься с `docs/recipes/gotchas.md` — там 35 способов молча всё сломать, все уже проверены на живых проектах.
