# Кант света: живая светящаяся рамка (BorderGlow)

Референс: **Creative Solution** (`website/src/components/sections/PricingSection.astro`
+ `src/lib/motion/sections/glow.ts`) — третий тариф в лестнице цен. Идея взята
у [reactbits BorderGlow](https://reactbits.dev/components/border-glow), но
и картинка, и механика хода собраны заново: оригинал в Chrome не работал
(§6.2), а его поведение «горит только под курсором» на статичной странице
почти не видно.

**Что получается.** По периметру тёмной карты бесконечно едет пятно света —
белое ядро, тёплый спад в акцент, ореол наружу и мягкая подсветка борта
внутрь. Курсор зашёл на карту — свет кратчайшей дугой уходит к ближайшей
точке канта и следует за курсором. Курсор ушёл — с того же места продолжает
круг с прежней скоростью. Ни морганий, ни перезапусков: карта всё время
«живая», но не мельтешит.

**На тач-экранах круг идёт точно так же** — пропадает только слежение за
пальцем. Соблазн выключить анимацию «раз наведения там всё равно нет» —
ловушка: неподвижный огонёк в углу карты читается не как эффект, а как
недогруженная картинка (проверено на живом сайте). Замирает свет ровно в
одном случае — `prefers-reduced-motion`.

Приём дорогой на вид и дешёвый по коду: **весь рисунок — CSS, а JS отвечает
ровно за две координаты**.

---

## 1. Разметка

Два слоя внутри карты, в каждом — «окно» (§2.2):

```astro
<article class="card" data-glow>
  <span class="card__halo" aria-hidden="true"><span class="card__win" /></span>
  <span class="card__edge" aria-hidden="true"><span class="card__win" /></span>
  <slot />
</article>
```

`data-glow` — метка для скрипта (§3), классы — для стилей (§2).

⚠️ **Узлы пишутся в разметке, а не скриптом.** Вставленный из JS элемент не
получит scoped-атрибут Astro (`data-astro-cid-*`) и останется без стилей —
эффекта не будет вовсе, при этом в консоли будет тишина. Скрипт трогает
только CSS-переменные на самой карте.

## 2. CSS: из чего состоит эффект

### 2.1 Рисунок: кольцо + пятно + свечение

Формула из трёх шагов, каждый — своим слоем:

```css
/* 1. кольцо канта — по всей карте; box-shadow повторяет скругление всегда */
.card__win::before {
  border-radius: <радиус карты>;
  box-shadow:
    inset 0 0 0 1.25px hsl(28 100% 93%),    /* белое ядро линии */
    inset 0 0 4px 0 hsl(24 100% 78% / 70%);  /* тёплый спад внутрь */
}
/* 2. видимую ДУГУ вырезает маска-пятно — радиальный градиент вокруг точки
      света (какими стопами — §2.2, и главное — ГДЕ он живёт) */
/* 3. свечение — drop-shadow ВНЕШНЕГО слоя, по альфе уже вырезанной дуги */
.card__edge {
  filter: drop-shadow(0 0 3px hsl(26 100% 76% / 95%))
          drop-shadow(0 0 7px hsl(16 100% 62% / 75%));
  opacity: var(--glow-op);
}
```

Ядро обязано быть почти белым: чистый брендовый акцент на почти чёрной карте
читается «тёмно-красной линией», а не светом — в любой палитре берите свой
акцент и поднимайте светлоту до ~90 % для ядра. `drop-shadow` работает по
альфе, поэтому свет ложится ровно вдоль дуги — и наружу на холст, и внутрь
на борт. Filter и маска обязаны жить на РАЗНЫХ узлах: filter одного узла
применяется раньше его маски, на общем узле она срезала бы всё свечение.

### 2.2 Движение БЕЗ перерисовки: «окно» и контр-движение

Наивная сборка — маска прямо на кольце, с центром в переменных:
`radial-gradient(... at var(--mx) var(--my), ...)`. Она работает — на
десктопе. На iOS каждый шаг света означает перерисовку слоя размером с
карту, а движок режет такие слои на растровые плитки и при покадровой
перерисовке обновляет их вразнобой: несвежие плитки у скруглений читаются
чёрными «уголками», а после скролла или возврата на вкладку плитка вовсе
остаётся протухшей — застрявший призрак свечения (§6.3).

Лечение — переупаковать ТО ЖЕ САМОЕ так, чтобы за кадр менялись только
трансформы:

```css
/* ОКНО: квадрат 2×--win-r, центр которого JS возит по канту.
   Маска СТАТИЧНА — пятно в собственном центре окна, не в (--mx, --my)! */
.card__win {
  --win-r: 160px;
  position: absolute; top: 0; left: 0;
  width: calc(var(--win-r) * 2); height: calc(var(--win-r) * 2);
  margin: calc(var(--win-r) * -1) 0 0 calc(var(--win-r) * -1); /* центр в (0,0) */
  transform: translate3d(var(--mx), var(--my), 0);   /* центр → точка света */
  overflow: hidden;                                  /* ограничивает растр */
  will-change: transform;
  mask-image: radial-gradient(closest-side circle at center,
    #000 6%, rgb(0 0 0 / .55) 46%, transparent 100%);
  mask-repeat: no-repeat; mask-size: 100% 100%;
}
/* КОЛЬЦО: карта-«призрак» в полный размер, контр-движением прибитая к
   настоящей карте: окно уехало на (mx,my) — кольцо на столько же назад. */
.card__win::before {
  content: "";
  position: absolute; top: 0; left: 0;
  width: var(--w); height: var(--h);   /* размер карты — пишет JS */
  transform: translate3d(calc(var(--win-r) - var(--mx)),
                         calc(var(--win-r) - var(--my)), 0);
  will-change: transform;
  /* + border-radius и box-shadow из §2.1 */
}
```

Сумма движений — ноль: кольцо всегда совпадает с картой, окно с маской
ездит по нему, `closest-side` окна равен прежнему радиусу пятна — картинка
попиксельно та же, что у «маски в точке курсора». Но маска, тени и фильтр
статичны: за кадр меняются два `transform`, композитор переставляет готовые
растры, перерисовки нет. Это и есть весь фикс мобильных багов.

Правило шире рецепта: **если что-то движется каждый кадр — двигаться должен
`transform`**; всё, что заставляет слой перерисовываться (маска или градиент
с переменными координатами, filter с меняющимися параметрами,
`background-position`), на телефоне вылезет боком.

### 2.3 Два слоя: линия и ореол

```css
.card { position: relative; isolation: isolate; }

.card__edge,
.card__halo {
  position: absolute;
  inset: 0;
  border-radius: inherit;
  pointer-events: none;
  z-index: -1;                       /* поверх фона карты, но ПОД её текстом */
  transition: opacity .25s ease-out; /* плавная смена яркости на ховере */
}
/* ореол: то же окно шире (--win-r ×1.6), кольцо толще и тусклее,
   drop-shadow длиннее */
.card__halo {
  filter: drop-shadow(0 0 10px hsl(12 100% 58% / 55%))
          drop-shadow(0 0 20px hsl(8 95% 54% / 34%));
  opacity: calc(var(--glow-op) * .9);
}
.card__halo .card__win {
  --win-r: 256px;
  mask-image: radial-gradient(closest-side circle at center,
    #000 10%, rgb(0 0 0 / .5) 52%, transparent 100%);
}
.card__halo .card__win::before {
  box-shadow:
    inset 0 0 0 2px    hsl(16 100% 64% / 55%),
    inset 0 0 14px 0   hsl(12 100% 60% / 38%),
    inset 0 0 34px 2px hsl(8 95% 56% / 20%);
}
```

Разная ширина пятен даёт переход цвета вдоль канта: в середине дуги видно и
белую линию, и тёплый ореол, к концам линия гаснет раньше. Вынос свечения за
карту (~30px от drop-shadow) обязан помещаться в вертикальные поля
обрезающего родителя, если карты лежат в ленте с `overflow-x: auto`, — иначе
срез прямой линией.

### 2.4 Слои под текстом: `z-index: -1` + `isolation: isolate`

`z-index: -1` кладёт слой **поверх фона родителя, но под его содержимое** —
ровно то, что нужно: свет не лезет на текст. Но это работает, только если
родитель сам образует стекинг-контекст; иначе слой провалится под фон карты
и исчезнет. `isolation: isolate` на карте — обязателен.

## 3. JS: одно число вместо трёх режимов

Вся механика хода — **одна переменная `t`**: положение света на периметре,
0…1, где 0 — середина верхней стороны, дальше по часовой.

| Режим | Что делает кадр |
| --- | --- |
| покой | `t += dt / LAP` — равномерный круг |
| курсор на карте | `t` тянется к проекции курсора на кант по кратчайшей дуге |
| курсор ушёл | снова `t += dt / LAP` — **с того же места** |

Именно поэтому нет ни прыжков, ни «перезапусков анимации»: режимы меняют
только правило приращения, а состояние у них общее. Это главная мысль
рецепта — не таймлайны на каждое событие, а одно число и три способа его
двигать.

```js
const LAP = 12;        // секунд на полный круг
const CATCH = 0.13;    // постоянная времени «догоняния» курсора (~0.4 с до цели)
const MAX_STEP = 50;   // мс: первый кадр после сна вкладки не должен телепортировать свет

const frac = (x) => ((x % 1) + 1) % 1;
/** Кратчайшая разница двух положений на кольце: [-0.5, 0.5). */
const shortest = (from, to) => frac(to - from + 0.5) - 0.5;

/** Длина контура скруглённого прямоугольника. */
const perimeter = (w, h, r) => 2 * (w - 2 * r) + 2 * (h - 2 * r) + 2 * Math.PI * r;

/**
 * Точка контура на расстоянии d от середины верхней стороны, по часовой.
 * Контур именно СКРУГЛЁННЫЙ: пятно света срезается клипом карты, и если вести
 * его по острому прямоугольнику, на каждом повороте центр пятна уходил бы на
 * ~10px наружу от скругления — свет моргал бы четыре раза за круг.
 */
function pointOnPath(w, h, r, d) {
  const arc = (Math.PI * r) / 2;
  const half = w / 2 - r, side = h - 2 * r, bottom = w - 2 * r;
  let s = d;
  if (s < half) return [w / 2 + s, 0];                     s -= half;
  if (s < arc) { const a = s / r - Math.PI / 2; return [w - r + r * Math.cos(a), r + r * Math.sin(a)]; }
  s -= arc;
  if (s < side) return [w, r + s];                          s -= side;
  if (s < arc) { const a = s / r;               return [w - r + r * Math.cos(a), h - r + r * Math.sin(a)]; }
  s -= arc;
  if (s < bottom) return [w - r - s, h];                    s -= bottom;
  if (s < arc) { const a = s / r + Math.PI / 2; return [r + r * Math.cos(a), h - r + r * Math.sin(a)]; }
  s -= arc;
  if (s < side) return [0, h - r - s];                      s -= side;
  if (s < arc) { const a = s / r + Math.PI;     return [r + r * Math.cos(a), r + r * Math.sin(a)]; }
  s -= arc;
  return [r + s, 0];
}

/* Обратная задача (ближайшая к курсору точка контура) — перебором по таблице
   выборок, а не формулой: 256 сравнений за кадр ховера дешевле одной ошибки
   в кусочной геометрии со скруглениями. Таблица строится в measure(). */
const SAMPLES = 256;
function samplePath(w, h, r) {
  const per = perimeter(w, h, r);
  const out = new Float64Array(SAMPLES * 2);
  for (let i = 0; i < SAMPLES; i++) {
    const [x, y] = pointOnPath(w, h, r, (per * i) / SAMPLES);
    out[i * 2] = x; out[i * 2 + 1] = y;
  }
  return out;
}
function nearestT(path, x, y) {
  let best = 0, bestDist = Infinity;
  for (let i = 0; i < SAMPLES; i++) {
    const dx = path[i * 2] - x, dy = path[i * 2 + 1] - y;
    const d = dx * dx + dy * dy;
    if (d < bestDist) { bestDist = d; best = i; }
  }
  return best / SAMPLES;
}
```

Цикл (vanilla `requestAnimationFrame`, GSAP не нужен):

```js
export function initBorderGlow(root = document) {
  const els = [...root.querySelectorAll('[data-glow]')];
  if (!els.length) return () => {};

  const cards = els.map((el) => ({ el, w: 0, h: 0, r: 0, path: null, t: 0.62, hover: false, px: 0, py: 0, seen: true }));
  const paint = (c) => {
    const [x, y] = pointOnPath(c.w, c.h, c.r, c.t * perimeter(c.w, c.h, c.r));
    c.el.style.setProperty('--mx', `${x.toFixed(1)}px`);
    c.el.style.setProperty('--my', `${y.toFixed(1)}px`);
  };
  const measureAll = () => cards.forEach((c) => {
    const box = c.el.getBoundingClientRect();
    c.w = box.width; c.h = box.height;
    // радиус читаем из стилей: он меняется вместе с раскладкой, а контур
    // света обязан совпадать с клипом карты
    const radius = parseFloat(getComputedStyle(c.el).borderTopLeftRadius) || 0;
    c.r = Math.max(0, Math.min(radius, Math.min(c.w, c.h) / 2));
    c.path = samplePath(c.w, c.h, c.r);
    // размер карты — в CSS: кольца-«призраки» в окнах повторяют её коробку
    c.el.style.setProperty('--w', `${c.w.toFixed(1)}px`);
    c.el.style.setProperty('--h', `${c.h.toFixed(1)}px`);
    paint(c);
  });

  measureAll();
  cards.forEach((c) => c.el.style.setProperty('--glow-op', '0.82'));
  addEventListener('resize', measureAll, { passive: true });
  // Возврат на вкладку и восстановление из bfcache: пока страницы не было на
  // экране, могли смениться размеры (поворот телефона) и раскладка. Свежий
  // обмер стоит копейки и снимает класс «ушёл и вернулся — эффект поехал».
  const wake = () => { if (!document.hidden) measureAll(); };
  document.addEventListener('visibilitychange', wake);
  addEventListener('pageshow', wake);

  const off = [() => {
    removeEventListener('resize', measureAll);
    removeEventListener('pageshow', wake);
    document.removeEventListener('visibilitychange', wake);
    cards.forEach((c) => ['--mx', '--my', '--w', '--h', '--glow-op'].forEach((p) => c.el.style.removeProperty(p)));
  }];

  // Единственный случай, когда свет стоит: движение по кругу тут И ЕСТЬ
  // анимация — гасить её нечем. Тач не исключение (см. интро).
  if (matchMedia('(prefers-reduced-motion: reduce)').matches) return () => off.forEach((fn) => fn());

  // Слежение за курсором — только точному указателю: на тач-экране
  // pointerenter/leave приходят по тапу и дёргали бы свет рывком к пальцу.
  const fine = matchMedia('(hover: hover) and (pointer: fine)').matches;

  for (const c of cards) {
    if (fine) {
      const enter = (e) => { c.px = e.clientX; c.py = e.clientY; c.hover = true;  c.el.style.setProperty('--glow-op', '1'); };
      const move  = (e) => { c.px = e.clientX; c.py = e.clientY; };
      const leave = ()  => { c.hover = false; c.el.style.setProperty('--glow-op', '0.82'); };
      c.el.addEventListener('pointerenter', enter);
      c.el.addEventListener('pointermove', move);
      c.el.addEventListener('pointerleave', leave);
      off.push(() => {
        c.el.removeEventListener('pointerenter', enter);
        c.el.removeEventListener('pointermove', move);
        c.el.removeEventListener('pointerleave', leave);
      });
    }
    // За экраном ход считаем, но стили не трогаем: blur-слой не должен
    // перерисовываться впустую. На мобилке это главный ограничитель расхода.
    const io = new IntersectionObserver((es) => { c.seen = es[es.length - 1].isIntersecting; }, { rootMargin: '25% 0px' });
    io.observe(c.el);
    off.push(() => io.disconnect());
  }

  let raf = 0;
  let prev = performance.now();
  const tick = (now) => {
    const step = Math.min(now - prev, MAX_STEP) / 1000;
    prev = now;
    for (const c of cards) {
      if (c.hover) {
        // Карта ездит вместе со скроллом, координаты курсора — оконные,
        // поэтому её положение читаем каждый кадр ховера (и только его;
        // размеры и таблицу контура держит measureAll).
        const box = c.el.getBoundingClientRect();
        const target = nearestT(c.path, c.px - box.left, c.py - box.top);
        c.t = frac(c.t + shortest(c.t, target) * (1 - Math.exp(-step / CATCH)));
      } else {
        c.t = frac(c.t + step / LAP);
      }
      if (c.seen) paint(c);
    }
    raf = requestAnimationFrame(tick);
  };
  raf = requestAnimationFrame(tick);
  off.push(() => cancelAnimationFrame(raf));

  return () => off.forEach((fn) => fn());
}
```

**Сближение — экспоненциальное и кадронезависимое.** Не `t += d * 0.1`
(на 120 Гц такой лерп вдвое быстрее, чем на 60), а
`1 - Math.exp(-dt / CATCH)`: одинаково на любом FPS и с любым лагом кадра.
Кратчайшую дугу даёт `shortest()` — свет идёт туда, где ближе, и на границе
`0/1` не разворачивается на полный круг.

([animations-motion.md §2](animations-motion.md)):

## 4. Бюджет

Кадр стоит: одна запись двух CSS-переменных → пересчёт `transform` четырёх
маленьких узлов (окно и кольцо в двух слоях) и переоценка drop-shadow на
GPU. **Ни одной перерисовки слоя**: маски и тени статичны, растры готовы —
композитор только переставляет их. Это и есть весь бюджет; остальное —
гигиена:

- `IntersectionObserver` с запасом 25 % — за экраном ход считается (свет «не
  отстаёт»), стили не пишутся;
- при `prefers-reduced-motion` — статика: ни цикла, ни слушателей;
- на тач-экранах цикл работает без изменений (отдельного дешёвого режима не
  понадобилось), слушателей указателя там нет вовсе;
- rAF сам замирает в фоновой вкладке; `visibilitychange`/`pageshow` нужны не
  для паузы, а чтобы **переобмерить карту после возврата** — за время сна
  могли смениться размеры и раскладка;
- `getBoundingClientRect` — только в кадрах ховера, в покое размеры берутся
  из кэша (обновляется на `resize` и на пробуждении);
- `will-change` не ставим: `translate3d` и так поднимает узел на свой слой,
  а у iOS жёсткий GPU-бюджет на вкладку ([gotchas.md](gotchas.md) §7).

## 5. Крутилки

| Что | Где | Смысл |
| --- | --- | --- |
| `LAP` | JS | секунд на круг: 12 — спокойно, <6 — суетливо |
| `CATCH` | JS | 0.13 — «быстро, но плавно»; 0.05 — почти телепорт; 0.3 — лениво |
| `--glow-spot` | CSS | база радиусов пятен: сколько канта горит вокруг точки |
| множители `--win-r` | CSS | 0.5 у линии / 0.8 у ореола — насколько ореол длиннее дуги |
| `inset 0 0 0 Npx` | CSS | толщина линии (1.25px) и кольца ореола (2px) |
| `--glow-op` | JS→CSS | яркость: 0.82 в покое / 1 под курсором |
| стопы градиентов | CSS | где кончается белое ядро и как быстро гаснет тёплый спад |

## 6. Грабли (все пойманы вживую)

1. **Кольцо из `padding` + `mask-composite: exclude` рвётся на скруглениях в
   iOS.** Внутренняя коробка маски (`content-box`) обрезается там прямым
   углом, и на каждом из четырёх углов квадратная «дырка» съедает кольцо
   целиком: свет идёт по стороне и резко пропадает на повороте. В Chrome всё
   в порядке — баг доезжает до прода и ловится с телефона. Лечение: рисовать
   кольцо `inset box-shadow` по скруглённой коробке (§2.1), а маской брать
   простое радиальное пятно **без `<geometry-box>`** (§2.2). Общее правило:
   на скруглениях не доверяйте `mask-clip: content-box/padding-box`.
2. **Маска на дефолтах даёт призрак в противоположном углу.** `mask-repeat`
   по умолчанию `repeat`, `mask-size` — `auto`; под `filter`'ом на iOS
   соседняя плитка рисует копию светового пятна по диагонали от настоящего,
   со швом-острым-углом. Если маска всё-таки нужна — прибивайте `no-repeat`,
   `0 0`, `100% 100%`, `border-box` явно. На десктопе не воспроизводится.
3. **Слой, который перерисовывается каждый кадр, на iOS «сыпется».** Даже с
   правильной маской остаются швы растровых плиток по контуру, «уголки» на
   скруглениях и **залипшие копии свечения после возврата на вкладку** —
   iOS режет большой слой на плитки и обновляет их вразнобой. Лечение не
   в подкрутке маски, а в отказе от покадровой перерисовки: та же картинка пересобирается как
   «окно» + контр-движение, где за кадр меняются только трансформы (§2.2).
   Это и есть третья, живущая редакция эффекта.
4. **`filter` применяется РАНЬШЕ маски.** Если всё же строите свечение
   фильтром по маске, они обязаны жить на РАЗНЫХ узлах (маска на
   псевдоэлементе, фильтр на обёртке): на одном узле маска срежет весь
   ink-overflow фильтра, и эффекта не будет вовсе — при идеальном computed
   style.
5. **`conic-gradient` в `mask-image` Chrome отрисовывает мимо элемента.**
   Оригинальный BorderGlow вырезает светящуюся дугу коническим градиентом от
   угла на курсор — на карте 488×700 Chrome ставит его центр за пределами
   слоя, и свет не попадает на кант ни при каком угле (проверено подстановкой
   заведомо жёлтой рамки: с `mask-image: none` она есть, с коническим —
   исчезает целиком, а `linear-gradient(#000,#000)` в той же маске работает).
   Радиальное пятно + кольцо дают ту же картинку без этой мины.
6. **`mix-blend-mode: plus-lighter` (как в оригинале) выжигает ореол в белое
   на светлом фоне.** Если холст страницы светлеет (у нас — анимация
   «рассвета»), режимы смешивания использовать нельзя: только обычная альфа.
7. **`z-index: -1` без `isolation: isolate`** — слой уходит под фон карты и
   пропадает (§2.4).
8. **Узел, вставленный скриптом, теряет scoped-стили Astro** (§1).
9. **Ореол настоящей геометрией расширяет прокручиваемую область.** В
   горизонтальной ленте (`overflow-x: auto`) слой, торчащий за карту, и
   добавит пикселей к ширине прокрутки, и обрежется по вертикальным полям
   трека (у `overflow-x` вертикаль тоже становится обрезающей). Поля трека
   держите больше выноса ореола, а вынос — в пределах `padding-inline`
   (§2.3).
10. **Лерп по кадрам вместо `exp(-dt/τ)`** — разная скорость на 60/120 Гц и
   рывок после лага вкладки (§3).
11. **Соблазн выключить анимацию на тач «раз ховера там нет».** Пойман на
   проде: свет замирал в углу карты и выглядел артефактом вёрстки, а не
   эффектом. Выключать надо не движение, а слежение за указателем; цену
   кадра снижать в CSS (§2.3), а не отказом от анимации.
