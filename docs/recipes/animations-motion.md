# Анимации и движение: система, а не зоопарк

Референсы: эталон-каталог (data-reveal, marquee, immersive zones),
эталон-витрина (sticky-стек, слайд-шоу). В стартере готовы: reveal-система
(BaseLayout + global.css), `<Marquee>`, sticky-стек (`StackedShowcase`).

## 1. data-reveal — единая система появления контента (в стартере)

ОДИН IntersectionObserver на сайт вместо анимационной библиотеки:

```html
<div data-reveal>появлюсь при скролле</div>
<div data-reveal style="transition-delay: 70ms">я — вторым (stagger)</div>
```

Как устроено (и почему именно так):
- CSS прячет `[data-reveal]` ТОЛЬКО под `html.reveal-ready`; класс ставит
  скрипт в `<head>`, если есть JS и нет reduced-motion. Нет JS / краулер /
  reduce → контент просто виден. **SEO не страдает никогда.**
- На `astro:before-swap` класс переносится на входящий документ — после
  SPA-навигации reveal продолжает работать.
- Элементы, уже находящиеся во вьюпорте при инициализации (top < 92 % экрана),
  показываются мгновенно — никакого «мигнуло и проявилось».
- Stagger — просто `transition-delay` инлайном: `${(i % 3) * 70}ms` в `.map()`.

## 2. SPA-safe скрипты — паттерн, без которого всё ломается

С `<ClientRouter/>` инлайн-скрипты и DOM живут по разным правилам. Канон:

```js
// A. Документ-уровневые слушатели/синглтоны — ОДИН раз за жизнь документа:
if (window.__fooInit) return;
window.__fooInit = true;
document.addEventListener('click', delegatedHandler);

// B. Пер-страничная привязка к DOM — на каждую навигацию:
document.addEventListener('astro:page-load', initPageDom);
// page-load срабатывает и на первой загрузке — прямой вызов НЕ нужен.

// C. Таймеры/обсерверы — чистить перед перевзведением:
if (window.__fooTimer) clearInterval(window.__fooTimer);
window.__fooTimer = setInterval(tick, 4000);
```
Нарушение C — классический баг «карусель крутится вдвое быстрее после
каждого возврата на главную».

Четвёртый случай не покрывается ни одним из трёх правил выше: **window-
слушатель, чьё тело замыкает конкретный DOM-узел текущей страницы**
(`const header = document.getElementById(...)`, взятый один раз при первом
вызове). Guard-флаг на `window` (правило A) корректно не даёт навесить
второй слушатель — но после свапа `<body>` захваченная переменная
продолжает указывать на отсоединённый узел с прошлой страницы, и эффект
(например, «шапка сжимается при скролле») перестаёт что-либо делать без
единой ошибки в консоли. Лечение — читать узел из `document` заново внутри
самого обработчика (а не из захваченной переменной) либо перепривязывать
слушатель на `astro:before-swap`/`astro:page-load` вместе с узлом. Подробный
разбор — [scroll-pitfalls.md](scroll-pitfalls.md#6-window-слушатель-привязанный-к-пер-страничному-dom).

## 3. IntersectionObserver-гейтинг таймеров

Ничего не тикает вне экрана. Слайд-шоу эталона-витрины стартует только при
приближении (`rootMargin: 200px`, guard `started` + `disconnect()`); карусель
отзывов эталона-каталога паузится на `document.hidden` и когда блок ушёл из
вьюпорта. Экономит батарею и CPU-бюджет мобильных.

## 4. Marquee (в стартере: `<Marquee>`)

CSS-only: трек дублируется дважды, `translateX(-50%)` бесконечно, пауза на
hover, статика при reduce. Для логотипов клиентов, бейджей, фото-лент.
Продвинутая версия эталона-каталога (наклонные ряды с параллаксом от скролла) — см.
`WorksMarquee.astro` там же; главная её гоча описана в [gotchas.md](gotchas.md)
(iOS не лениво-грузит картинки под transform).

## 5. Sticky-паттерны (уже в стартере)

- **Стек карточек** (`StackedShowcase`): `position: sticky; top: 5rem` +
  возрастающий `z-index` — карточки наезжают друг на друга при скролле. 0 JS.
- **Sticky-колонка цены**: `grid lg:grid-cols-[1fr_400px] items-start` +
  `sticky top-24` у правой колонки. ⚠️ Обязателен `items-start` — без него
  grid растягивает колонку и sticky не работает.
- Красивый приём эталона-витрины для текста поверх фото: градуированный blur —
  `::before` с `backdrop-filter: blur(8px)` под маской
  `mask-image: linear-gradient(to top, black 15%, transparent 55%)`.

## 6. Immersive dark zones (рецепт, эталон-каталог)

Секция «владеет» страницей: пока `[data-immersive-zone]` в центре вьюпорта
(`rootMargin: '-45% 0px -45%'`), на `body` висит класс тёмной темы, и вся
страница плавно темнеет; соседние элементы с `[data-dark-adapt]` меняют цвет
текста. `Set` активных зон → один boolean-класс (смежные зоны не мигают).
Реализация ~50 строк: `эталон-каталог/website/src/components/ImmersiveDarkZones.astro`.

## 7. Пин-сцены со скрабом (в стартере: `<ScrollScene>`)

Секция «залипает», а по прокрутке в ней собирается товар. Отдельный рецепт со
всеми инвариантами — [scroll-scenes.md](scroll-scenes.md); там же почему пин
сделан на `position: sticky`, а не ScrollTrigger'ом (у sticky высота в `svh`,
и ресайз пересчитывает CSS без реинита сцены).

## 8. Когда БРАТЬ библиотеку (GSAP)

Эталон-каталог подключает GSAP ровно для ОДНОГО компонента — мобильного меню со
staggered-анимацией и прерыванием таймлайнов (`tl.kill()` при быстрых тапах).
Правило: GSAP оправдан для оркестрации (последовательности, прерывания) — не
для «появления при скролле» (это делает data-reveal бесплатно) и не для
пин-скраба (см. §7).

Если всё же берёте `ScrollTrigger` — под тяжёлую пин-сцену с восстановлением
позиции скролла между переходами, например — у него отдельный список
капризов (тихо игнорируемый `scrub` без `animation`, обязательный реинит
сцены при смене брейкпоинта, влияние ленивой pin-распорки на высоту всего
документа): [scroll-pitfalls.md](scroll-pitfalls.md).

## 9. Кант света на карточке (рецепт, Creative Solution)

Светящаяся рамка, которая живёт сама: пятно света едет по периметру карты, на
ховере кратчайшей дугой уходит к курсору и следует за ним, после ухода
продолжает круг с того же места. Весь рисунок — CSS (кольцо канта тенью, дугу
вырезает статичная маска-«окно», за кадр меняются только `transform`), JS
двигает одну переменную — положение на периметре. На тач-экранах круг идёт
так же (пропадает только слежение за пальцем) — иначе неподвижный огонёк
читается как артефакт вёрстки. Отдельный рецепт со всем кодом и одиннадцатью
граблями (все главные ловятся только с телефона и сводятся к одной: слой,
который перерисовывается каждый кадр, на iOS сыпется швами и призраками —
двигаться должен `transform`) — [border-glow.md](border-glow.md).

## 10. Правила
- Каждая анимация имеет reduce-ветку (глобальный медиазапрос уже в стартере).
- Анимируйте только `transform`/`opacity` (композитор, не layout).
- `will-change` — точечно и временно, у iOS жёсткий GPU-бюджет на вкладку.
