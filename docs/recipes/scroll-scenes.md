# Скролл-сцены: пин + скраб по кадрам

Секция «залипает» на экране, а по мере прокрутки в ней что-то происходит:
товар собирается, поворачивается, раскрывается в разрезе. Приём дорогой на
вид и предельно капризный в реализации — в шаблоне лежит готовый
`<ScrollScene>` (`src/components/sections/ScrollScene.astro`), обкатанный на
конструкторе боевого проекта за пять итераций правок заказчика.

Приёмка сцены — отдельный документ: [qa/scroll-scene-qa.md](../qa/scroll-scene-qa.md).

## Быстрый старт

```bash
# 1. Ролик → секвенция кадров
node scripts/frames-from-video.mjs assembly.mov src/assets/scene/seq
```

```astro
---
import ScrollScene from '../components/sections/ScrollScene.astro';
import { asset, assetsIn } from '../lib/images/registry';

const frames = [1, 2, 3, 4].map((i) => asset(`scene/stage-${i}.webp`)!.src);
const seq = assetsIn('scene/seq').map((e) => e.img.src);
---
<ScrollScene
  frames={frames}
  seqFrames={seq}
  seqKeys={[5, 44, 90, 140, 183]}
  stages={[
    { title: 'Каркас', description: 'Сухой массив и берёзовая фанера.' },
    { title: 'Механизм', description: 'Металл, а не пластиковые шестерни.' },
    { title: 'Наполнение', description: 'Пружинный блок, ППУ, Memory Foam.' },
    { title: 'Обивка', description: 'Износостойкие ткани, ровные швы.' },
  ]}
>
  <div slot="outro">…заголовок и CTA…</div>
</ScrollScene>
```

`--scene-top` задаёт отступ под фиксированную шапку:
`.scroll-scene { --scene-top: 5rem; }`.

## Почему без GSAP

ScrollTrigger умеет пин и скраб из коробки, но приносит с собой pin-spacer,
цикл `refresh()` и обязательный реинит при смене брейкпоинта — сцена,
собранная на мобильном режиме, остаётся мобильной после растягивания окна,
пока её не пересоздашь.

Пин на `position: sticky` этого класса проблем не имеет: высота спейсера
задана в `svh`, поэтому поворот устройства и ресайз пересчитывает сам CSS.
Инерцию даёт rAF-lerp в четыре строки. Зависимостей — ноль.

GSAP остаётся оправдан там, где нужна оркестрация таймлайнов с прерываниями
(см. [animations-motion.md](animations-motion.md) §7), но для пин-скраба он
не нужен.

## Пин на ScrollTrigger вместо sticky — когда оправдано

Если проекту всё же нужен пин именно на `ScrollTrigger` (например, сцена
обязана участвовать в общем цикле `refresh()` с другими триггерами
страницы), помните: `pin-spacer` ScrollTrigger'а требует реинита сцены при
смене брейкпоинта (иначе сцена, собранная в мобильном режиме, остаётся
мобильной после растягивания окна) и меняет высоту документа не сразу, а
лениво — после `load` и приближения секции к экрану. Второе особенно больно
на страницах, которые ещё и **восстанавливают позицию скролла** между
переходами: сохранённый пиксель начинает указывать не туда, куда указывал в
момент сохранения. Полный разбор десяти граблей (плюс не связанные с
пином) — [scroll-pitfalls.md](scroll-pitfalls.md), в частности п.1 и п.8; про
то, как пин рвёт якорные ссылки и двигает `scrollY` при создании, — п.4, 9, 10.

## Инварианты: что ломается, если их нарушить

Каждый пункт — реальная правка заказчика, а не теория.

### 1. Такты равны и стыкуются без нахлёста

Сцена делится на равные такты: по одному на этап + доля на финал. Окна
полуоткрытые `[начало, конец)`.

- **Нахлёст** — на стыке в разных углах кадра на миг видны два титра. Звучит
  как «заголовки скачут». Перекрытия в 0.005 прогресса достаточно.
- **Зазор** — участок, где прокрутка ничего не меняет. Звучит как «скроллю,
  а оно застряло». Поэтому последний титр держится до появления финала.

### 2. Сцена обратима

Соблазн сделать анимацию «одноразовой» (показали — заморозили) велик,
особенно на мобиле. Не делать: после заморозки прокрутка перестаёт что-либо
менять, и это читается как поломка. Назад сцена обязана разбираться тем же
ходом колеса, каким собиралась.

### 3. Один набор окон на оба режима

Кадров два комплекта — базовый (по одному на этап) и полная секвенция. Легко
завести им разные окна титров: «пока этап собирается» для видео и «пока
показан кадр этапа» для базы. Так делать нельзя — наборы разъезжаются, и на
статичных кадрах титр опережает картинку на пункт. Окна одни, режим меняет
только источник картинки.

### 4. Кадр ролика мапится кусочно-линейно

В ролике этапы не равны по длительности: 44 / 90 / 140 / 183 кадра на
границах. Если гнать прогресс в кадр линейно, границы этапов разъезжаются с
границами тактов. `seqKeys` задаёт ключевые кадры, компонент интерполирует
между ними — «этап собран» приходится ровно на смену титра.

### 5. Секвенция — в `<canvas>`, не свапом `src`

Подмена `src` у `<img>` заставляет браузер декодировать картинку заново на
каждом шаге скраба: сцена мерцает пустотой. `drawImage` в канвас держит
предыдущий кадр, пока не готов новый — мерцать физически нечему. Замер после
перехода: 0 кадров дольше 80 мс за полный проезд туда-обратно.

### 6. Байты — только по подходу

Секвенция из 184 кадров весит ~3,5 МБ. Условие загрузки — `load` **И**
близость к секции (`rootMargin: 250%`), а не «или»: `load` наступает через
доли секунды и один съедает всю экономию. Базовые кадры ждут в `data-src`,
потому что `loading="lazy"` ниже сгиба не гарантия
([images-assets.md](images-assets.md#когда-loadinglazy-не-спасает)).

Готовность считается по `decode()`, а не `onload`, иначе первый показ мигает
недекодированным кадром. Под Save-Data и 2G секвенция не качается вовсе —
сцена живёт на базовых кадрах.

### 7. Композиция центрируется целиком

Кадр и закрывающий блок — одна вертикальная стопка, центрированная в
пин-области. Если прижать кадр к верху, а финал к низу, между ними появится
дыра на пол-экрана. Ширина кадра поэтому ограничена дважды: колонками
«воздуха» под титры и высотой окна за вычетом финала.

## Что настраивать под проект

| Проп | Дефолт | Когда менять |
| --- | --- | --- |
| `beatVh` | `55` | сцена «летит» — увеличить; тянется — уменьшить |
| `mediaWidth` | `70%` | длинные титры по бокам требуют больше воздуха |
| `aspect` | `16 / 9` | под пропорцию ролика |
| `seqKeys` | — | обязателен, если этапы в ролике не равны по длительности |
| `--scene-reserve` | `360px` | высота закрывающего блока (влияет на размер кадра) |

Титры чередуют стороны автоматически (нечётные справа, чётные слева). Если
в кадре по центру сверху что-то происходит (например, подушки прилетают
сверху), не ставьте титр по центру — перекроет.
