# Каталог с programmatic SEO

Референс: эталон-каталог (окна/двери/балконы/порталы × пластик/алюминий). Паттерн для
любого бизнеса с линейкой продуктов/услуг: мебель на заказ, стройматериалы,
услуги клиники, тарифы. В стартере готовы schema-билдеры
(`productSchema`, `serviceSchema`, `itemListSchema` в `src/lib/schema.ts`);
структура страниц — по этому рецепту.

## Трёхуровневая структура

```
/katalog/                 УРОВЕНЬ 1 — индекс каталога
  сетка категорий         ItemList JSON-LD, каждая карточка = ссылка вниз
    │
/okna/                    УРОВЕНЬ 2 — коннектор категории
  редакционное интро      БЕЗ Product-схемы! Его работа — распределить
  MaterialFork:           трафик по листьям и забрать общий запрос
  «пластик или алюминий?» («окна купить») широким контентом
    │
/okna/plastikovye/        УРОВЕНЬ 3 — материальный лист (money page)
  галерея + характеристики  Product JSON-LD (+ цены AggregateOffer)
  глубокий SEO-текст        сюда 301-ятся все старые гранулярные SKU
```

Почему так, а не 20 страниц-SKU: у гранулярных страниц («окно эконом»,
«окно стандарт», «окно премиум») дублирующийся тонкий контент — они
каннибализируют друг друга. Эталон-каталог свернул SKU в материальные листы
и закрыл переезд 301-ми. Урок: **страниц столько, сколько РАЗНЫХ интентов,
а не сколько позиций в прайсе.**

## Структурированные данные по уровням

| Уровень | JSON-LD | Билдер в стартере |
| --- | --- | --- |
| Индекс | `ItemList` из карточек | `itemListSchema({name, items})` |
| Коннектор | только BreadcrumbList | (авто в BaseLayout) |
| Лист | `Product` с ценами | `productSchema({...})` |
| Услуга (/uslugi/montazh/) | `Service` | `serviceSchema({...})` |

Правила из боевого опыта эталона-каталога:
- **Никогда не вешайте aggregateRating/review на Product** без реальных
  отзывов ЭТОГО товара на ЭТОЙ странице — ручные санкции Google. Реальный
  рейтинг живёт один раз, на LocalBusiness.
- `AggregateOffer` (lowPrice+highPrice) для «от … до …» — честнее и даёт
  цену в сниппете. Продукт-схемы Google Merchant хотят `hasMerchantReturnPolicy`
  и `shippingDetails` — добавьте, если целитесь в товарные листинги.
- `@id`-ссылки: Product.manufacturer и Service.provider указывают на
  `{site}/#organization` (в стартере уже так) — граф связан, данные не дублируются.

## Контент-коллекция для товаров

Эталон-каталог определяет коллекцию `products` (MDX): category enum, material enum,
brands[], features[], тех-спеки, SEO-поля, флаги isHit/isNew, priority.
В стартере добавьте по образцу `src/content.config.ts` (схему — в
`src/config/schemas.ts`, см. `docs/CONTENT.md`):

```ts
const catalog = defineCollection({
  loader: glob({ pattern: '**/*.mdx', base: './src/content/catalog' }),
  schema: z.object({
    title: z.string(),
    category: z.enum(['окна', 'двери']),   // под проект
    description: z.string().max(160),
    image: z.string(),
    features: z.array(z.string()).default([]),
    lowPrice: z.number().optional(),
    highPrice: z.number().optional(),
    order: z.number().default(0),
    draft: z.boolean().default(false),
  }),
});
```
Дальше `getCollection('catalog')` → карточки уровня 1 и `getStaticPaths`
листьев. (Эталон-каталог исторически собирает листья вручную — коллекция удобнее.)

## Миграция со старого сайта: карта 301

Если у клиента был сайт — старые URL это ссылочный вес и позиции. Соберите ВСЕ
старые адреса (Вебмастер → страницы в поиске; access-логи; sitemap старого
сайта) и сведите каждый к ближайшему новому в `astro.config.mjs redirects` (у
эталона-каталога ~79 правил: `/shop/*.html`, `/photos/*`, `/uslugi/*.html`).

⚠️ Гоча trailing-slash: при `trailingSlash:'always'` НЕ добавляйте правил
`'/x' → '/x/'` — это один и тот же роут, получится вечный редирект на себя.
Только кросс-страничные переезды (старый URL → ДРУГАЯ страница).

## Внутренняя перелинковка (бесплатный буст)

- Индекс ↔ коннекторы ↔ листья связаны хлебными крошками (уже в BaseLayout).
- Из блог-статей — контекстные ссылки на листья каталога (эталон-витрина делает целую
  секцию «что рядом» со ссылками на гайды — тот же приём наоборот).
- Футер: колонка «Продукция» со ссылками на все коннекторы.
- На листьях — `<ComparisonTable>` пластик-vs-алюминий со ссылкой на
  соседний лист: закрывает сравнительный интент и линкует горизонтально.
