# Админ-панель: деплой-кнопка, метрики, логи, трафик

Оба проекта (эталон-витрина и эталон-каталог) несут одинаковую самодельную
админку — страница `/admin/` + горстка SSR-эндпоинтов. Владелец сайта деплоит
кнопкой из браузера, смотрит трафик и логи без SSH. Паттерн скопирован между
проектами почти без изменений — значит, зрелый. В стартер не включён кодом
(нужен SSR + серверные права); подключается копированием референсных файлов.

## Состав (что копировать)

Из `эталон-каталог/website/src/` (свежее версии эталона-витрины):

| Файл | Роль | Что менять |
| --- | --- | --- |
| `lib/auth.ts` | Web Crypto HMAC-сессии (без зависимостей) | ничего |
| `middleware.ts` | гард `/admin*` и `/api/admin/*` | ничего |
| `pages/admin/login.astro` + `index.astro` | UI | брендинг |
| `pages/api/admin/login.ts` / `logout.ts` | вход/выход, rate limit 5/мин | ничего |
| `pages/api/admin/deploy.ts` | деплой-движок | пути + имя сервиса |
| `pages/api/admin/system.ts` | CPU/RAM/диск/uptime/SHA | имя сервиса |
| `pages/api/admin/commits.ts` | список коммитов GitHub | `OWNER/REPO` |
| `pages/api/admin/logs.ts` | journalctl-вьювер | имя юнита |
| `pages/api/admin/traffic.ts` | дашборд из Caddy-логов | путь к логу |

Env на сервере: `ADMIN_PASSWORD_HASH` (SHA-256 от пароля), `COOKIE_SECRET`
(`openssl rand -hex 32`), `GITHUB_PAT` (fine-grained, Contents: Read-only).

## Ключевые находки паттерна (почему он хорош)

1. **Аутентификация без зависимостей.** Сессия = HMAC-SHA256-подписанный
   токен `base64url(admin:{ts}).base64url(sig)` через Web Crypto, cookie
   `HttpOnly + SameSite=Lax`, TTL 24 ч. Пароль — один, хеш в env. Никаких
   баз и библиотек.
   Тонкость эталона-каталога: флаг `secure` у cookie ставится по РЕАЛЬНОМУ протоколу
   запроса — на временном `http://IP` (до подключения домена) логин не
   зацикливается.
2. **Деплой-движок** (`deploy.ts`): mutex `deploying` (409 если занято) →
   `git fetch` → `git pull` ИЛИ `git checkout <sha>` (**коммит-пиновка =
   встроенный откат** на любой коммит из списка) → `npm ci` → `build` →
   `rsync -a --delete dist/` в runtime-каталог → **HTTP-ответ отправляется
   ДО рестарта**, сам рестарт через `setTimeout(500)` + sudo systemctl —
   иначе процесс убьёт себя раньше, чем ответит браузеру.
3. **Дашборд трафика без аналитики**: парсинг JSON-логов Caddy (tail 50k
   строк) → запросы час/день/неделя, топ-10 страниц (с фильтрами ботов:
   `/wp-`, `.php`, `.env`), почасовые бакеты, коды ответов. Источник данных
   уже есть: JSON-лог пишет Caddy-конфиг, который выпускает панель
   **Freim Deploy** при подключении сайта.
4. **Наименьшие привилегии**: sudoers-файл разрешает `deploy` ровно четыре
   команды systemctl над одним юнитом (такой доступ панель **Freim Deploy**
   уже настраивает при установке сайта).

## Подключение к проекту на стартере

1. Включите hybrid-режим (node adapter в `astro.config.mjs`).
2. Скопируйте файлы из таблицы, замените пути/имена (`SRC_DIR`, `DEPLOY_DIR`,
   имя сервиса, `OWNER/REPO`).
3. `robots.txt` уже закрывает `/admin` (в стартере с рождения); страницы
   админки — `noindex, nofollow`.
4. Сгенерируйте секреты, добавьте в `/var/www/<site>/.env`.
5. Проверьте из браузера: логин → метрики → деплой тестового коммита →
   откат на предыдущий.

## Специфика эталона-витрины: редактор данных через git

У эталона-витрины в админке есть эндпоинт `rating.ts`: владелец правит JSON с рейтингом
(отзывы Яндекса) прямо из браузера, а сервер **коммитит и пушит** изменение
в репозиторий (`git add && commit && push`) — чтобы следующий `git pull`
деплоя не конфликтовал. Паттерн «контент-правка без CMS» — подходит для
любых мелких данных (цены, акции, контакты), но помните: сервер получает
push-права в репо (PAT с Contents: Read-Write).
