# Попапы и вовлечение: показать вовремя, не бесить

Референсы: эталон-каталог `LeadPopup.astro` (боевая версия), эталон-витрина
`PromoBanner.astro`.
В стартере: `common/LeadPopup.astro`, `common/PromoBanner.astro` (базовые
версии тех же движков).

## Главный принцип: state machine на sessionStorage

Все решения «показывать ли» — это флаги в хранилище, а не таймеры в вакууме:

| Флаг | Что значит |
| --- | --- |
| `app_lead_submitted` | заявка уже отправлена — попапы молчат до конца сессии (ставит `lead-form.ts`) |
| `app_lp_start` | время старта сессии — задержки НАКОПИТЕЛЬНЫЕ через страницы |
| `app_lp_engaged` / `app_lp_exit` | этот триггер уже показывался в сессии |
| `app_promo_dismissed` (localStorage) | промо закрыто — молчим N дней |

Накопительная задержка — важная деталь: «показать через 25 секунд» значит
25 секунд НА САЙТЕ, а не на конкретной странице (`DELAY_MS - elapsed()` при
каждой навигации). Иначе активный пользователь, скачущий по страницам,
никогда не увидит попап, а залипший на первой — увидит слишком рано.

## Триггеры LeadPopup (что в стартере)

1. **engaged** — 25 c накопительного времени. Не срабатывает, если: заявка
   уже отправлена / на экране видна обычная лид-форма (IntersectionObserver
   по `[data-lead-form]`) / фокус в поле ввода.
2. **exit-intent (десктоп)** — `mouseout` без `relatedTarget` через верхнюю
   кромку (`clientY <= 0`), не раньше 15-й секунды сессии.
3. **Cooldown 15 c после закрытия** — закрыл крестиком, увёл курсор вверх —
   не выстрелит exit-intent сразу же.

Каждый триггер — одноразовый на сессию. Успех формы (`success="event"`) →
попап рисует свою карточку «Спасибо» и сам закрывается через 4 c.

## Продвинутые приёмы эталона-каталога (в рецепте, не в коде)

- **Mobile back-trap.** На тач-устройствах exit-intent не существует. Эталон-каталог
  ловит первый Back: `history.replaceState(null,'') + pushState(...)` — первое
  нажатие «назад» снимает фиктивную запись истории и открывает попап вместо
  ухода. Жёстко гейтится: только тач, только вход с главной, ≥15 c, не
  returning-визитор. URL не меняется, боты не затронуты. Сознательно НЕ
  включён в стартер — паттерн агрессивный, включайте осознанно под нишу.
  Референс: `эталон-каталог/website/src/components/sections/LeadPopup.astro`.
- **Скоринг варианта.** Эталон-каталог выбирает текст попапа («смета» для сравнивающих
  цены) по `comparisonScore()`: ≥3 просмотренных страниц + price/compare-регексы
  в utm_term/referrer + returning-флаг. История страниц пишется в
  `sessionStorage` из Layout.
- **iOS-safe scroll lock.** `body{position:fixed; top:-scrollY}` при открытии;
  при закрытии временно `scrollBehavior='auto'` перед `scrollTo` — иначе
  smooth-scroll «уезжает» на глазах.

## PromoBanner (паттерн эталона-витрины, в стартере)

Вежливый промо-виджет в углу — не модалка, не перекрывает контент:
- накопительная задержка (общий сид `app_lp_start` с попапом);
- закрыл → **7 дней тишины** (localStorage timestamp);
- ждёт, пока решён cookie-баннер и вкладка видима (иначе ретрай каждые 4 c);
- z-index НИЖЕ cookie-баннера.

Эталон-витрина дополнительно ротирует 3 варианта карточки (localStorage-счётчик
`count % variants.length`) и лениво грузит фон только активного варианта
(`new Image().onload` → показать). Нужна ротация — смотри
`эталон-витрина/src/components/common/PromoBanner.astro`.

## Пассивное вовлечение (в стартере: EngagementTracking)

`engaged_visitor` (60 c, раз в сессию) и `deep_scroll` (60 % глубины, только
если страница длиннее 1.4 экрана). Зачем: это микро-конверсии для обучения
рекламных стратегий Директа, пока настоящих лидов мало. Плюс цель
`popup_shown{trigger}` — мерить, какой триггер реально конвертит.

## Правила приличия
- Один попап на сессию на триггер; после заявки — тишина навсегда.
- Никогда не показывать поверх открытой лид-формы.
- Escape, крестик, клик по фону — всё закрывает; фокус внутрь при открытии.
- `role="dialog" aria-modal="true"` обязательны.
